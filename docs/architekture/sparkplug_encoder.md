# Sparkplug Encoder

## Purpose

The `SparkplugEncoder` converts the gateway's internal data model into
Sparkplug B compliant messages.

It is the only component that knows the Sparkplug B protocol.

The encoder is completely independent from sensors, MQTT and hardware.

---

## Responsibilities

- Build Sparkplug B topics
- Encode Protobuf payloads
- Maintain Sparkplug sequence numbers
- Produce binary payloads ready for transmission

The encoder never

- communicates with sensors
- publishes MQTT messages
- stores measurements
- communicates with databases

---

## Position in the Architecture

```text
DeviceData
      │
      ▼

SparkplugEncoder
      │
      ▼

SparkplugPayload
      │
      ▼

MQTTPublisher
```

---

## Public Interface

```cpp
class ISparkplugEncoder
{
public:

    virtual ~ISparkplugEncoder() = default;

    virtual SparkplugPayload encode(const DeviceData& deviceData, MessageType messageType) = 0;
};
```

---

## Supported Message Types

```cpp
enum class MessageType
{
    NBIRTH,
    DBIRTH,
    DDATA,
    NDEATH,
    DDEATH
};
```

Command messages (`NCMD`, `DCMD`) belong to a future Sparkplug decoder and
are therefore outside the responsibility of the encoder.

---

## Internal Responsibilities

Internally the encoder performs several independent steps.

```text
DeviceData
      │
      ▼

Build Topic
      │
      ▼

Create Protobuf Payload
      │
      ▼

Append Metrics
      │
      ▼

Update Sequence Numbers
      │
      ▼

SparkplugPayload
```

The public interface exposes a single `encode()` function while the
implementation delegates these steps to private helper methods.

---

## Sequence Management

The encoder maintains the Sparkplug sequence counters.

```cpp
uint8_t bdSeq_;
uint8_t seq_;
```

### bdSeq

Represents the Birth/Death sequence.

- changes only when a new Edge Node session starts
- remains constant during normal operation

### seq

Represents the message sequence.

- increments after every published Sparkplug message
- wraps from 255 back to 0
- resets to 0 whenever a new NBIRTH message starts a new session

---

## Produced Output

The encoder produces a complete Sparkplug message.

```cpp
SparkplugPayload
{
    MqttTopic topic;
    BinaryPayload payload;
};
```

The MQTT Publisher does not interpret Sparkplug messages.

It only publishes the topic and binary payload produced by the encoder.

---

## Design Principles

- Single Responsibility Principle
- Stateless with respect to measurements
- Protocol encapsulation
- Transport independence
- Hardware independence

---

## Future Extensions

Future versions may support

- Sparkplug Templates
- Dataset Metrics
- Property Sets
- Metric Aliases
- Compression

Support for command messages (`NCMD`, `DCMD`) will be implemented by a
dedicated Sparkplug decoder.

The MQTT Last Will (`NDEATH`) is generated by the encoder but will later be
configured by the MQTT Publisher during connection establishment. This keeps
all Sparkplug-specific knowledge inside the encoder while allowing the MQTT
Publisher to remain protocol-independent.
