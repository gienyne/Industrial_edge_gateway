# Data Models

## Overview

The Industrial Edge Gateway is built around a common internal data model.

Instead of allowing each software component to exchange hardware-specific
or protocol-specific data, all information is converted into a shared
representation before it is processed by the gateway.

This approach provides a clear separation between hardware acquisition,
business logic and communication protocols.

The complete data flow is illustrated below.

```text
Sensor
    │
    ▼
SensorReading
    │
    ▼
Metric
    │
    ▼
DeviceData
    │
    ▼
SparkplugPayload
    │
    ▼
MQTT Broker
```

Each model has a single responsibility and is independent from the
implementation details of the surrounding layers.

---

# Data Models

## Configuration

The `Configuration` model contains all runtime parameters required by the
gateway.

It does not represent sensor or machine data.

Typical configuration values include

- MQTT Broker
- MQTT Port
- MQTT Client ID
- Sparkplug Group ID
- Sparkplug Edge Node ID
- Publish Interval
- MQTT QoS
- MQTT Retain Flag

The configuration is shared by the different gateway components but is
kept separate from the application data.

---

## SensorReading

`SensorReading` represents the raw output produced by a hardware sensor.

Each sensor provides its own reading model because different sensors
measure different physical quantities.

Current Sprint

```text
DHT11Reading
├── temperature
├── humidity
├── timestamp
└── valid
```

```text
ShockReading
├── detected
├── timestamp
└── valid
```

```text
LightReading
├── intensity
├── timestamp
└── valid
```

Separating hardware-specific readings from the remaining software keeps
sensor drivers simple and independent.

---

## Metric

A `Metric` represents one standardized measurement inside the gateway.

Regardless of whether the value originates from an ESP32 sensor,
an OPC UA server or a Modbus device, every measurement is converted into
the same internal representation.

Conceptually a metric contains

```text
Metric
├── name
├── datatype
├── value
└── timestamp
```

Examples

```text
Temperature = 24.8 °C
Humidity    = 56 %
Shock       = true
Light       = 820
```

The gateway core processes only metrics and never interacts directly with
hardware-specific structures.

---

## DeviceData

`DeviceData` groups all metrics belonging to one physical device.

Instead of processing isolated measurements, the gateway always processes
complete device snapshots.

Conceptually

```text
DeviceData
├── deviceId
├── metrics
└── timestamp
```

Example

```text
ESP32

├── Temperature
├── Humidity
├── Shock
└── Light
```

Future industrial devices follow exactly the same model.

Example

```text
Robot ABB

├── Temperature
├── Motor Current
├── Speed
└── Alarm
```

Because every data source is converted into the same representation,
the remaining gateway components remain unchanged.

---

## SparkplugPayload

`SparkplugPayload` represents the final message generated by the
Sparkplug Encoder.

It contains all information required for MQTT publication.

Conceptually

```text
SparkplugPayload
├── topic
├── payload
├── messageType
├── seq
└── bdSeq
```

The MQTT Publisher operates only on this model and is completely
independent of sensors, industrial protocols and internal metrics.

---

# Design Decisions

The internal data models follow several architectural principles.

## Separation of Responsibilities

Each model represents exactly one abstraction level.

```text
Sensor
        │
        ▼
SensorReading
        │
        ▼
Metric
        │
        ▼
DeviceData
        │
        ▼
SparkplugPayload
```

No model combines responsibilities from different layers.

---

## Hardware Independence

The gateway core never processes hardware-specific data.

Only the Sensor Connector knows the underlying hardware.

Every other component operates exclusively on the common internal data
model.

---

## Protocol Independence

The internal models do not depend on Sparkplug B, MQTT, OPC UA or Modbus.

Communication protocols are handled only by dedicated components such as
the Sparkplug Encoder or future machine connectors.

---

## Extensibility

Adding a new data source requires only a new connector.

Example

```text
OPCUAConnector

ModbusConnector

RESTConnector
        │
        ▼
Metric
        │
        ▼
DeviceData
```

The remaining gateway architecture remains unchanged.

---

# Summary

The internal data model forms the foundation of the Industrial Edge
Gateway.

It provides

- a common representation for all measurements;
- clear separation between hardware and communication protocols;
- a modular and extensible architecture;
- a stable software foundation for future industrial machine integration.
